# MZ-AniCharaDB カードフォーマット仕様ノート
**スキーマバージョン: MiZu_Character_Profile_v1.2602.01**
作成日: 2026-02-22

---

## 概要

このドキュメントは、MZ-AniCharaDBのキャラクターカード（JSON）を独自フォームや手書きで作成する際のガイドラインです。公式カードメーカー（card_form.html）を使わず、独自ツールやテキストエディタで直接JSONを作成・編集する場合の基準として参照してください。

---

## ファイル命名規則

```
{作品名}_{キャラ名}_{枝番}_{タイムスタンプ}.json
```

例:
```
Just_Because!_小宮恵那_001_260115_1203.json
ダイの大冒険_ダイ_1989_260222_0900.json
ダイの大冒険_ダイ_2020_260222_0900.json
```

**枝番について**  
同一作品・同一キャラの複数バリエーションを管理するためのフィールドです。連番（001, 002…）でも年号（1989, 2020）でも任意の文字列で構いません。ファイルマネージャーでのドラッグ範囲選択を考慮し、`{作品名}_{キャラ名}_{枝番}` の部分は固定で保つことを推奨します。

**タイムスタンプ**  
`YYMMDD_HHMM` 形式。カード作成時点の日時。

---

## キーの必須レベル定義

| レベル | 意味 |
|--------|------|
| **処理必須** | 欠けるとインポート処理が止まる |
| **管理必須** | 欠けると運用上の追跡が困難になる |
| **推奨** | あると品質・検索性が向上する |
| **任意** | 作品・キャラによって入れる |

## JSONフォーマット仕様

### トップレベル構造

```json
{
  "header":                 {},   // 処理必須
  "name":                   "",   // 処理必須
  "work":                   "",   // 処理必須
  "profile":                {},   // 推奨
  "product":                {},   // 推奨
  "tags":                   {},   // 推奨
  "rating":                 {},   // 推奨
  "personality_parameters": {},   // 推奨
  "extended":               {},   // 任意
  "assets":                 [],   // 任意（将来用）
  "comments":               {}    // 推奨
}
```

---

### header ブロック【処理必須】

```json
"header": {
  "schema":         "MiZu_Character_Profile_v1.2602.01",  // 処理必須・固定値
  "uuid":           null,                                  // カードメーカーではnull。アップローダー側で付与
  "sid":            null,                                  // アップローダー側で付与
  "content_hash":   null,                                  // normalizer.phpで付与
  "generated_at":   "2026-02-22T04:13:00.942Z",           // 処理必須・ISO8601形式
  "first_registered": "2026-02-22T04:13:00.942Z",         // 管理必須・マージ時は旧カードから引き継ぐ
  "last_updated":   "2026-02-22T04:13:00.942Z"            // 管理必須・更新のたびに書き換え
}
```

**補足**
- `uuid` / `content_hash` は手書き時も `null` でよい。それぞれアップローダーJS・normalizer.phpが付与する
- `first_registered` はマージ処理で新カードを生成する際、旧カードの値を引き継いで保持すること
- 日時はすべてISO8601（UTC）で記述する

---

### name / work【処理必須】

```json
"name": "小宮恵那",
"work": "Just Because!"
```

- 両方とも空文字・null は不可
- 表記は公式に準じることを推奨（略称・通称は `tags` で補完）

---

### profile ブロック【推奨】

```json
"profile": {
  "name_reading": "こみや えな",       // 推奨・読み仮名（スペース区切り）
  "height_cm": {
    "value": 166,                       // 数値 or null
    "is_official": true                 // 公式設定かどうか
  },
  "weight_kg":  { "value": null, "is_official": false },
  "birthday":   { "value": null, "is_official": false },
  "blood_type": { "value": null, "is_official": false },
  "custom_fields": [                    // 任意・作品固有の基本情報
    { "label": "学年",   "value": "高校2年生", "is_official": true },
    { "label": "所属部活", "value": "写真部",  "is_official": true }
  ]
}
```

**公式設定フィールドのルール**
- 値が不明・未設定の場合は `"value": null`
- `is_official: true` = 原作・公式設定に明記されている値
- `is_official: false` = 推定・考察・非公式の値
- `birthday` の value は `"yyyy/mm/dd"` 形式の文字列（ISO日付型に変換しない）

---

### product ブロック【推奨】

```json
"product": {
  "アニメ制作": "PINE JAM",
  "year":       2017,"
  "担当声優(正)":   "Lynn",
  "chara_voise_2nd":		 " M・A・O（ラジオ企画にて）", //
  "原作":       "鴨志田一"
  "character_designer_film_": "田中将賀"
  "character_designer_novel": "田中将賀" // アニメと小説でキャラデザが異なる場合など、作品ごとにキーを追加していくことを想定
}
```

- キーは日本語で自由記述
- 将来的に名寄せマスターで英語キーに統一予定。過渡期は日本語・英語の混在を許容

---

### tags ブロック【推奨】

```json
"tags": {
  "affiliations":   ["椚ヶ丘高等学校", "写真部"],  // 作品内の客観的所属・属性
  "character_tags": ["ショートカット", "負けヒロイン", "カメラ女子"]  // 類型・ジャンル的属性
}
```

**affiliations と character_tags の使い分け**

| affiliations | character_tags |
|--------------|---------------|
| 作品内で明示される所属・役職・グループ | キャラ類型・外見的特徴・ジャンルタグ |
| 宇治北高校、ユーフォニアムパート | ツンデレ、ボクっ娘、負けヒロイン |

---

### rating ブロック【推奨】

```json
"rating": {
  "外観":   2,
  "性格":   5,
  "環境背景": 3
}
```

- 値は 1〜5 の整数
- キーは `"外観"` `"性格"` `"環境背景"` の3項目が基本
- 4項目以降は任意追加可（作品固有の評価軸など）
- 評価はカード登録者の主観による

---

### personality_parameters ブロック【推奨】

```json
"personality_parameters": {
  "軸1": {
    "labels": ["社交的", "内向的"],
    "values": [8.5, 1.5],
    "anchor": 0
  },
  "軸2": {
    "labels": ["行動的", "慎重"],
    "values": [9.2, 0.8],
    "anchor": 0
  }
}
```

**ルール**
- キーは `"軸1"` `"軸2"` … の連番
- `labels` は必ず2要素。左が基準側
- `values` は必ず2要素。合計が 10.0 になること
- `anchor` は補正基準側のインデックス（通常 `0` = 左側が固定）
- 未評価時のデフォルト値は `[5.0, 5.0]`
- 基本5軸（社交的/内向的・行動的/慎重・直感的/論理的・情緒的/理性的・楽観的/悲観的）は全カード推奨。独自軸の追加も可

**合計10.0の補正ルール**  
片側だけ入力した場合、`anchor` 側の値を固定として相手側を `10 - anchor値` で自動補完する。

---

### extended ブロック【任意】

作品・キャラ固有のパラメーターを自由に追加するブロック。

```json
"extended": {
  "キャンプスキル": {
    "テント設営": 7.0,
    "料理":       6.5,
    "焚き火":     7.5
  },
  "能力パラメーター": {
    "物理攻撃": 8.5,
    "魔法攻撃": 9.5
  }
}
```

**ルール**
- ブロック名・パラメーター名は日本語で自由記述
- 値は数値（小数可）
- スケールは原則 0〜10。作品固有のスケールを使う場合はコメントか別途メモで明示
- 将来的に名寄せマスターで英語キーへの対応表を管理予定

---

### assets ブロック【任意・将来用】

現時点では空配列で固定。画像・音声などのアセット参照を将来追加予定。

```json
"assets": []
```

---

### comments ブロック【推奨】

```json
"comments": {
  "intro": [
    "廃部寸前の写真部を救うべく、ベストショットを求めて奔走する活発な後輩。"
  ],
  "evaluation": [
    {
      "content":     "潔く行動する姿勢と、振られた後の涙が印象的。",
      "author_uuid": null
    }
  ]
}
```

- `intro` は配列（1要素が基本）。キャラの簡潔な説明文
- `evaluation` は配列。直近3件程度が目安
- `author_uuid` はコメント投稿者のUUID。単独運用時は `null` でよい

## マージ処理時のルール

同一作品・同一キャラで内容に差異があるカードが競合した場合（`03b_merge` に送られた場合）：

1. 旧カード・新カードを比較リストに記録
2. 目視で各キーの採用値を選択し新カードを生成
3. `first_registered` は旧カードの値を引き継ぐ
4. `last_updated` は新カード生成日時に更新
5. 旧カードをmainDBから削除・インデックスから除去
6. 新カードを通常のADD登録フローで登録

## 手書きチェックリスト

JSONを手書き作成する際の確認項目：

- [ ] `schema` が `"MiZu_Character_Profile_v1.2602.01"` になっているか
- [ ] `name` と `work` が空でないか
- [ ] `generated_at` / `first_registered` / `last_updated` がISO8601形式か
- [ ] `uuid` / `content_hash` が `null` になっているか（手書き・カードメーカー使用時）
- [ ] `personality_parameters` の各軸の `values` 合計が 10.0 か
- [ ] `birthday` の `value` が文字列形式（`"yyyy/mm/dd"`）か
- [ ] ファイル名が `{作品名}_{キャラ名}_{枝番}_{タイムスタンプ}.json` の形式か
